# Forge Sales Desk

An offline-first sales negotiation and pipeline workspace for B2B manufacturing and engineering solution sales. The app uses local seeded data and deterministic browser-side rules; it does not call an AI service or external API.

## Setup

1. Install Node.js 18 or newer.
2. Run `npm install`.
3. Run `npm run dev` and open the local URL printed in the terminal.

## Pricing and margin rules

- Delivery baseline is the sum of headcount × monthly rate × utilized man-months. Utilized man-months are `headcount × deployed duration × utilization percentage`; durations can use half-month increments. The planner also shows a man-day equivalent using 22 working days per month.
- The target quote is calculated at a 50% gross margin: `baseline / (1 − 0.50)`.
- The walk-away floor is calculated at a 35% gross margin: `baseline / (1 − 0.35)`. This uses the gross margin definition consistently; it is not a 35% markup on cost.
- The resource planner lets a user change headcount, seniority tier, rate, start month, deployed duration, and utilization. The resource Gantt reflects start and duration, while cost excludes idle time before deployment.
- Milestones demonstrate Figma design and AI work in parallel from month 1, coding through month 2, QA beginning in month 3 after that coding milestone completes, and acceptance/handover at the end. These are planning defaults; role start dates and utilization remain editable.
- The default QA example is one tester at ₹2,00,000/month for 1.5 months at 100% utilization, for ₹3,00,000 total.
- The seniority action reduces rates on non-critical roles by 9%; core engineering and project management are protected.
- Margin health uses green at 45% and above, amber from 35% to 44%, and red below 35%.

## Deterministic negotiation playbook

`src/lib/negotiation-engine.ts` compares the client counter to the computed floor and blocks a below-floor counter. Otherwise it returns a recommended counter and selects technical arguments from the size of the target-to-counter gap. Large gaps surface phased scope, tooling tolerances, and lifecycle reliability; smaller gaps emphasize QA and delivery assurance. These templates are fixed local rules and are not generated by a model.

The customer negotiation history panel is empty on first launch by design. Sales teams can enter actual segment, sector, quote, first counter, final price, result, objection, and response records. Data stays in browser local storage. The displayed counter and close discount summaries derive only from records the team enters. The sector filter also shows responses used on won deals as an evidence-based playbook; there are no fabricated claims about Indian customer behavior.

## Deployment notes

- Node.js 22 is pinned for both hosts. Render can use the included `render.yaml` Blueprint, which builds with `npm ci && npm run build` and starts with `npm start`.
- On Vercel, import the GitHub repository as a Next.js project. The default build command is `npm run build`; the Node version is pinned by `package.json`.
- The app does not have a shared database. Resource settings and negotiation history use browser local storage, while deal additions are held in page state. Data is not shared between the Render and Vercel domains and new deals are not retained after a page reload. Treat the hosted app as a demo until durable, authenticated storage is added.

## Seed data

Five sample industrial and software deals and four sales representatives are defined in `src/data/mock-data.ts`. All displayed records are illustrative. Edits to the resource model are held in page state for the current browser session.
