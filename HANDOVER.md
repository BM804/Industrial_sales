# Forge Sales Desk

Forge Sales Desk is a shared sales pipeline and negotiation workspace. The frontend is a Next.js app for Vercel; the API and PostgreSQL database run on Render.

## Working features

- Add, edit, delete, search, filter, and move opportunities through sales stages. Pipeline metrics are calculated from saved records; the app starts empty rather than showing fictional customers.
- Model role experience, headcount, rate, start month, duration, and utilization. Costs use deployed effort, and the planner reports man-months and man-days.
- Edit milestone start and duration. Moving implementation also moves QA to the first available month after coding; the QA resource schedule and cost follow it.
- Use the local rules-based counter-offer simulator and floor-price guardrail.
- Add and remove real negotiation-history records. Sector summaries and the response playbook are calculated from those saved records; no customer behavior is invented.
- All opportunity, plan, milestone, and negotiation records are stored in Render Postgres and shared by people using the same workspace.

## Deploy the backend and database to Render

1. Push this repository to GitHub.
2. In Render, create a **Blueprint** and select this GitHub repository. Render reads `render.yaml` and creates the API service plus PostgreSQL database.
3. When prompted, set `APP_LOGIN_PASSWORD` to a strong password of at least 12 characters. `APP_SESSION_SECRET` is generated by Render. Keep both secret values private.
4. Wait for the API health check to pass. Copy the service URL, for example `https://forge-sales-api.onrender.com`.
5. If using a custom frontend domain, set `WEB_ORIGINS` on the Render service to the exact Vercel and custom-domain origins, comma-separated, then redeploy the API. Standard Vercel `*.vercel.app` URLs and localhost are allowed by default.

The Blueprint uses paid Render plans for an always-on API and durable PostgreSQL storage. Check the plan and price shown by Render before confirming the Blueprint. Render's free Postgres expires 30 days after creation and is unsuitable for long-term workspace data.

## Deploy the frontend to Vercel

1. Import the same GitHub repository into Vercel as a Next.js project.
2. Add `NEXT_PUBLIC_API_URL` with the Render API service URL (no trailing slash).
3. Deploy or redeploy. Open the Vercel URL and sign in with the `APP_LOGIN_PASSWORD` configured on Render.

For later code changes, push to the connected Git branch; Vercel and Render deploy from Git automatically. Vercel environment-variable changes require a new deployment.

## Local development

- Frontend: `npm ci`, set `NEXT_PUBLIC_API_URL` in a local `.env.local`, then run `npm run dev`.
- Backend: create a PostgreSQL database, set `DATABASE_URL`, `APP_LOGIN_PASSWORD` (12+ characters), and `APP_SESSION_SECRET`, then run `npm ci` and `npm start` from `backend/`.
- Set `WEB_ORIGINS=http://localhost:3000` for local frontend access if the backend has a custom origin list configured.

The workspace uses one shared password, not individual user accounts or role-based permissions. Sign-in sessions expire after seven days. Negotiation recommendations are deterministic templates, not AI-generated advice.
